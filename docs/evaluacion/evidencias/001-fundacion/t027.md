## Flujo implementado

TechnicalScreen → useAppInformation → InformacionAplicacionContext → función del caso
de uso suministrada por AppProvider. La composición y el adaptador permanecen sin cambios.
Presentación solo consume tipos/resultados propios; no importa infraestructura ni Supabase.

El hook inicia la consulta al montar la vista, convierte sus resultados en cargando,
exito o error y permite reintentar. Un ref bloquea invocaciones duplicadas antes de
resolver la promesa. Montaje/generación de solicitud invalidan las respuestas anteriores
al cambiar la función del contexto o desmontar. También controla rechazo inesperado o
ausencia de proveedor sin filtrar detalles internos.

La pantalla sustituye el texto introductorio de versión por nombre, versión y descripción
reales del resultado. Conserva título, explicaciones técnicas, organización y navegación.
Carga y error tienen avisos polite; el error muestra «Reintentar». Mientras carga no se
ofrece esa acción y el hook también bloquea solicitudes duplicadas. «Volver al inicio»
permanece disponible en todos los estados. Se reutilizan los componentes compartidos,
incluidos escalado de texto y controles mínimos de 48×48 dp. No se añade StatusMessage,
galería vacía ni funcionalidades de negocio de tareas posteriores.

## Pruebas nuevas

Archivo reproducible: tests/presentation/use-app-information.test.mjs.
Se usa React/ReactDOM ya instalado, sin dependencias nuevas. El hook se monta mediante
createRoot/act reales con un probe sin nodos hijos sobre un host DOM inerte mínimo.
No se simulan useState/useEffect/useContext. Los casos del hook ejercitan:

1. Carga inicial, bloqueo de duplicados, error y reintento exitoso con caso de uso real.
2. Éxito con composición/caso de uso/adaptador reales a través del contexto.
3. Respuesta obsoleta ignorada, desmontaje y rechazo de reintento tras desmontar.
4. Texto y acciones de la pantalla para carga/éxito/error, conservando el regreso.
5. Error controlado sin proveedor.
6. Error controlado ante rechazo inesperado de la función recibida.

El caso de vista usa renderizado React de servidor, sustituye primitivas RN/UI y la
salida del hook en la frontera para comprobar las ramas y el cableado de los botones.
No prueba interacción nativa, medidas táctiles reales, efectos de un navegador real
ni TalkBack. El host inerte solo permite verificar el ciclo de vida de React del probe.
Es una prueba técnica automatizada, no una prueba E2E Android.

El script test existente ahora añade esta suite después de arquitectura/unitarias;
lint incluye tests/presentation. Solo se ajustaron esos dos scripts de package.json:
dependencias, versiones, lockfile y demás opciones permanecen intactos.
